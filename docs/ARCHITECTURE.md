# Android runtime architecture

`RambleApp` owns the Room database, encrypted settings and private-audio maintenance. `MainActivity` only configures the Android window and hosts the flow. `RambleFlow` coordinates navigation/state; provider, folder-access, settings, transcript, welcome and license screens are separate composables. Shared visual components live in `AppChrome`. User messages come from `res/values/ui_strings.xml` and the Android-compatible Hebrew catalog `res/values-iw/ui_strings.xml`. Compose is presentation only: it grants trees, validates a key, changes settings, retries exceptional failed items and requests work. It never implements transcription by opening a web page or invoking an AI agent.

`SourceReader` enumerates only enabled sources covered by explicit persisted SAF grants, including supported Samsung/Xiaomi layouts and custom folders. Activation persists its own baseline; regrant preserves cutoff/baseline. `FinalizedMp4` accepts completed non-fragmented single-track AAC MP4 only: finite atom sizes, final movie/media durations, consistent sample/time/chunk tables and offsets bounded inside actual mdat. Two equal proofs >=60 seconds apart plus stable metadata and an eligible recorded date automatically queue the job. Snapshotting uses actual descriptor length (not potentially stale SAF size), validates the copied proof and source again. Unsupported/open/unknown-date files wait without manual confirmation. Schemas 1 and 2 migrate to schema 3 without resetting baselines, credentials or jobs. The new planComplete flag defaults to true for old atomic chunk batches and false for new incremental plans. See AUTOMATIC-COMPLETION.md.

`ScanWorker` runs periodically and on app-open/repair. `ProcessWorker` holds a Room lease, uses finite invocations and checks pause/network rules before each request. Its queue lives in Room, outside WorkManager's trigger data. A per-chunk attempt is marked sending before the remote request. A known successful result is committed; an uncertain request remains blocked until the user acknowledges possible repeat cost. Key/profile versions are retained so switching providers doesn't accidentally route an existing partially processed job into another API account.

`AudioPlanner` streams through Android media codecs into contiguous 16 kHz mono PCM WAV chunks of at most five minutes. Files have actual WAV headers; the app doesn't split compressed bytes. Each completed window is hashed and committed before decoding the next. Preparation yields within the worker budget and resumes by seeking with preroll to the next timestamp-aligned window, rather than decoding the completed prefix. Uploads wait for planComplete. Missing unfinished chunks can be repaired individually. Chunks are verified and persisted before provider upload. The source content hash and per-chunk hashes protect resume and immutable planning. Multiple audio tracks are rejected for now rather than silently discarding one; this limitation is surfaced as a recording requiring attention.

`ProviderApi` uses fixed Groq/OpenAI HTTPS endpoints, bounded requests/responses and no automatic HTTP retries/redirects for paid submissions. No maintainer key, configurable arbitrary server or hosted Ramble provider is present.

`LocalExport` assembles UTF-8 canonical text in private app storage, publishes to app-owned MediaStore Downloads or an explicitly chosen SAF tree, and retains local text independently of Drive. `DriveExport` obtains scoped Google authorization, binds the account, provisions a normal My Drive folder and reconciles stable generated IDs/hashes on upload retries. A Drive failure never marks an already-transcribed chunk pending again. External assistants need their own authorized Drive connector.

No application code changes Samsung native recorder, Phone call-capture settings, Side-button mapping or recording announcements. The guide opens settings/manual instructions only. Only an optional microphone permission is requested for the in-app first-recording trial; no call-log/contact/Accessibility/all-files permission is requested.

`TrialRecorder` is an Android ViewModel holding a foreground-only MediaRecorder and a 30-second timer. On Stop it closes AAC/M4A and invokes `AppRecordings.submit`, creating one durable `source=app` queue job. Existing SourceReader snapshot routing dispatches app-owned inputs to UUID-only private storage and keeps hash/proof checks; external SAF scanning and baseline rules are unchanged. The worker accepts the app source without an external folder grant. Cancel/ON_STOP before save releases the microphone, discards only the unsaved trial and queues nothing. Saved trial state is restored from the queue/preferences, including the DB-before-preference crash window.


## Review hardening

External `QuickRecordActivity` launches always require an explicit tap to start or stop. It never trusts fromApp/controls extras to grant authority. `InternalRecordActivity` is non-exported; only in-app entry or an app-created immutable tile PendingIntent can invoke immediate recording. No second launcher icon is added.

HTTP 400/404/413/415/422 responses are definite rejections and do not become ambiguous paid attempts. DNS/connect/TLS failures before requestBodyStart enter a safe automatic network retry. Once upload may have started, lost/5xx/malformed outcomes remain uncertain and require approval. These are separate from 401/403 key repair and 429 throttling. A small wake worker schedules eligible planning/network/storage work without holding other recordings behind a delayed provider job.

Private audio retention and deletion are implemented by AudioRetention; source-folder originals and external exports are outside its ownership. Deletion holds the processor lease and leaves only a minimal origin tombstone against automatic reimport. Shared staging and retention mutations are serialized. Explicit sharing can reintroduce a previously deleted file; periodic source scanning cannot.

Folder onboarding always waits for Continue after a grant, including when both sources are connected. Returning to review also stays on that page. Transcription defaults to the interface language unless the user has explicitly selected another language or Auto detect.
